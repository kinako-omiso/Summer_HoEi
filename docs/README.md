## ブランチ規則
- developブランチからissueごとにブランチを作成。
- ブランチ名は issue/[issue番号]。例えばissue48番のタスクをする際は`issue/48`。
- **作業完了後**はリモートにプッシュし、Pull Requestを作成。
- mainブランチには動作確認を終えた動くコードのみをマージする(ギリギリになってゲームが動かない！！ってことを避けるため)。

### ブランチフロー
```
main ── develop
        |
        ├── issue/1
        ├── issue/2
        ├── issue/3
        └── issue/...
```

### それぞれのコマンド
- 今いるブランチから新しく**ローカルに**ブランチを作成
    ```
    git checkout -b <ブランチ名>
    ```
    例えばissue/48ブランチを作成したかったら
    ```
    git checkout -b issue/48
    ```
    > **注意:**
    -b オプションは新しく作成という意味です。<br>
- 今いるブランチから新しく**ローカル**に作成し、**リモート**にある(既存の)ブランチと紐づけ
    ```
    git checkout -b <作成するローカルブランチの名前> origin/<リモートにあるブランチ名>
    ```
    例えばローカルにissue/48というブランチを作成し、リモートにあるissue/48ブランチと紐づけたい時、
    ```
    git checkout -b issue/48 origin/issue/48
    ```
     > **注意:**
    gitでたびたびでてくるoriginとはリモートリポジトリのことだと思っててください。厳密には違う気がするけどよくわかんない。<br>
- 今いるブランチから既存のブランチへ移動
    ```
    git checkout <既存のブランチ名>
    ```
    例えば今いるブランチがdevelopブランチだとして、issue/48ブランチに移動して作業したいときは
    ```
    git checkout issue/48
    ```
    > **注意:**
    このコマンドで-bは必要ありません。先ほど述べたように-bオプションは新規作成という意味のためです。もともとcheckoutコマンドはその名の通りブランチを移動するコマンドです。できることめっちゃ増えてよくわからんくなってるらしいけど。<br>

## コミットメッセージ
コミットメッセージは以下をもとにに適宜やった作業内容がわかるように記述してください。思いつかん場合は例をそのまま書いてもらって大丈夫です。<br>
例
```
#<issue番号> <あれば作業内容を>
```
例えばissue48の作業を完了した場合、コミットメッセージは
```
#48
```
だけでもいいですし
```
#48 化けものの移動を実装
```
とかでもいいです。作業途中の場合は
```
#48 〇〇の処理のみ実装
```
とか書くといいんじゃないでしょうか。

### それぞれのコマンド
- コミットするコマンドはステージング(後述)している状態で
    ```
    git commit -m "#48 化け物の移動を実装"
    ```
- 直前のコミットメッセージを書き直したい場合は
    ```
    git commit --amend -m "コメント"
    ```
    直前のコミットをリモートにプッシュ済みの場合は
    ```
    git push -f origin <リモートのpush先ブランチ>
    ```

## 実際の作業の流れ
1. Godotを開く<br>
2. Godotの作業ディレクトリでVSCodeを開く(おすすめはGodot開いたら左下のファイルシステムの中の任意のファイル(res://とか)を右クリックし、下のターミナルで開くを選択。ターミナルが立ち上がったらcode .を入力しEnter)<br>
3. VSCodeのターミナルを開く。(CTRL+＠)
4. リモートの変更を取り込む。(他の人が作業した内容を反映させるため。)以下のコマンドを入力する。<br>
    - developブランチに移動
        ```
        git checkout develop
        ```
    - リモートの変更の取り込み(pull)。
        ```
        git pull origin develop
        ```
    > **注意:**
    1回developブランチを移動する理由は他人の取り込むべき変更はdevelopブランチに統合(マージ)されているため。他の作業中のブランチ(issue/50等)は取り込まない。逆に、自分がリモートに上げた自分が作業中のissueのブランチに移動し、git pull.<br> 
    
    > **注意:**
        ``` 
        git pull
        ```
        だけでもpullはできる。後ろに引数を取らない(origin developなどをつけない)場合、今いるローカルブランチに紐付けられたリモートブランチの変更を取り込む。今いるブランチではいものを引数に取った場合、そのブランチの変更を今いるブランチに取り込むことになる。 <br>
        例：issue/3ブランチに今いるとして、issue/5の変更を取り込みたいときは
            ```
            git pull origin issue/5
            ```
        。
5. issueをみて作業用のブランチに移動する。
6. 作業用のブランチにいることを確認して作業。<br>  
    今いるブランチの確認
    ```
    git branch
    ```
    *がついているものが今いるブランチ。もしくはVSCodeの左下、![ここ](image.png)<br>
    をみると確認できる。
7. 作業最高！作業最高！
8. 一段落したらステージングする。ステージングとはgit上にコミットするデータを教える(選択する)こと。セーブするデータを選ぶ感じ。<br>
    以下のコマンドで変更したすべてのファイルをステージングできる。
    ``` 
    git add .
    ```
     > **注意:**
     オプションの . は今いるディレクトリを指す。add .　とすることで今いるディレクトリ全体のうち、変更されたものをステージングという意味になる。code . の場合、今いるディレクトリでVSCodeを開くという意味。code <任意のディレクトリ名>にするとそのディレクトリでVSCodeが開く。
    
9. ステージングしていることを確認したらコミットする。上述のコミットメッセージ参考。
    ```
    git commit -m "#<issue番号> 作業内容"
    ```

10. リモートにプッシュする。プッシュして初めてリモートに自分の変更が反映される。
    そのブランチで初めてプッシュする場合は
    ```
    git push -u origin <ブランチ名>
    ```
    二回目以降は
    ```
    git push origin <ブランチ名>
    ```
    もしくは
    ```
    git push
    ```
 > **注意:**
 ここから下はそのissueの作業が完了した場合のみ行ってください。

11. 作業を完了したこと、プッシュしたことを確認しプルリクエストを作成する。githubのページを開き、Pull Requestをクリック<br>

Merge先をmianからdevelopブランチに変更し、コメントにissue番号のみを記入(#[issue番号])し作成。<br>
